# Telemetry Station SDK

Open-source C firmware support for devices that send structured telemetry through satellite-connected hardware, including the upcoming Pacific Gyre Bear Module.

The SDK is designed for firmware engineers building optimized Mobile-Originated (MO) telemetry messages and, where needed, parsing Mobile-Terminated (MT) messages.

## Payload workflow

Telemetry Station keeps payload optimization and schema-to-code generation in the web app:

1. Open the [Telemetry Station Payload Optimizer](https://telemetrystation.com/payload-optimizer).
2. Define your sensor fields and message layout.
3. Select **Telemetry Station Device SDK** as the C output. Coming soon.
4. Download:
   - `telemetry_payload.h`
   - `telemetry_payload.c`
5. Add both files to your firmware project.
6. Populate `telemetry_payload_values_t` with live sensor values.
7. Call `telemetry_payload_encode()` and send the resulting bytes through your satellite transport.

Example:

```c
telemetry_payload_values_t values = {
    .latitude = sensor.latitude,
    .longitude = sensor.longitude,
    .message_sequence = sequence,
};

size_t payload_bytes = 0;
size_t payload_bits = 0;

if (!telemetry_payload_encode(
        &values,
        payload,
        sizeof(payload),
        &payload_bytes,
        &payload_bits)) {
    /* Handle invalid values or insufficient buffer capacity. */
}
```

## Repository boundary

This repository contains the public C integration layer and examples. It does **not** contain the Telemetry Station Payload Optimizer implementation, browser decoder, schema optimizer, or TypeScript/JavaScript code.

Schema-specific C is generated by Telemetry Station and then added to the firmware project by the engineer.

Recommended project layout:

```text
include/
src/
generated/
  telemetry_payload.h
  telemetry_payload.c
examples/
tests/
```

## Build

```sh
cmake -S . -B build
cmake --build build --parallel
ctest --test-dir build --output-on-failure
```

You must install [cmake](https://cmake.org) to run these commands.

## Encoding format

Generated payload code follows the schema configured in the Payload Optimizer, including field order, MSB-first bit packing, zero padding of the final byte, signed integer encoding, scaled decimal encoding, and length-prefixed variable fields.

## Hardware

The SDK is intended to support customer-built satellite connected devices and hardware such as the upcoming Telemetry Station Bear Module. Hardware-specific modem, power, UART, provisioning, and transport code should remain separate from the generated payload.
